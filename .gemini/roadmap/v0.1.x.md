# Planejamento de Evolução: API Response (v0.1.x)
Objetivo: Transformar a Response em um motor de fluxo de dados universal, Pure Kotlin, capaz de 
gerenciar o ciclo de vida de requisições com suporte nativo a metadados de paginação e integração 
fluida com MVI.

## v0.1.1: O Marco da Fundação (Structural Alignment)
Foco: Organizar o projeto para escala e pureza técnica.
- [x] Multi-module Refactoring: Separar a API em módulos distintos.
- [x] Ajustar android.yml e publish.yml em função da nova estrutura. 
- [ ] Implementar métricas de compilador compose para garantir a consistência do código, diagnosticar e otimizar a performance.
- [x] Dependency Cleanup: Remover dependências de UI do núcleo da API para garantir o status de "Pure Kotlin".
- [x] Documentação: Adicionar documentos explicativos para o projeto.

## v0.1.2: O Marco da Ergonomia (The Fluent Update)
Foco: Facilitar a manipulação de dados sem boilerplate.
- [x] Operadores Funcionais: Implementar map, mapError, onSuccess, onFailure e fold.
- [x] State Recovery: Adicionar suporte para que o estado Failure possa carregar opcionalmente o 
último dado válido (útil para cenários de erro com cache).
- [x] Failure Reasoning: Tipagem de erro aprimorada com ErrorReason (Network, Server, Business, Unknown).
- [x] Refatoração de Builders: Padronização de asResponse e asResponseFlow.

## v0.1.3: O Marco da Inteligência de Dados (Pagination & Metadata)
Foco: Preparar a API para alimentar componentes de coleção inteligentes.
- [x] Response Metadata: Criar objeto de metadados dentro do Success.
- [x] Stale-While-Revalidate: Permitir que o estado Loading carregue o dado anterior (previousData).
- [x] Timestamping: Controle automático de idade do dado para auxílio em lógicas de cache.
- [x] Pluggable Policy: Arquitetura de políticas para paginação e sincronização.

## v0.1.4: O Marco da Produção (Reactive Flows)
Foco: Facilitar a criação de fluxos de dados no Repositório.
- [ ] Flow Builders: DSL responseFlow { ... } que gerencia o try/catch e emite os estados de Loading, 
Success ou Failure automaticamente.
- [ ] Bridge de Conversão: Extensões para converter o Result<T> nativo do Kotlin e 
Retrofit.Response<T> diretamente em Response<T>.
- [ ] Polling Support: Facilitar a criação de fluxos repetitivos que emitem Response.

## v0.1.5: O Marco da Testabilidade (Testing DSL)
Foco: Garantir que testar fluxos de dados seja simples.
- [ ] Test Utilities: Criar assertions customizadas como assertSuccess(), assertErrorType<T>().
- [ ] Mocking Helpers: Facilitar a criação de instâncias de Response para testes unitários em ViewModels.
